# Видение продукта

## 1. Проблема

Государственные учреждения и коммерческие организации продолжают обмениваться бумажными документами и их сканированными копиями. Информация из таких документов нередко переносится в учетные и другие информационные системы вручную. Особенно трудоемка обработка документов с большим количеством текста, многостраничными таблицами и неоднородной структурой.

Ручной перенос данных увеличивает стоимость документооборота и сроки обработки, создает риск ошибок и затрудняет использование накопленных сканов для поиска и автоматизированного анализа.

## 2. Видение и цель продукта

**Моя цель — разработать универсальный сервис, который автоматически преобразует PDF-документы в структурированный Markdown, сохраняя печатный текст, заголовки, абзацы, таблицы и логический порядок содержимого.**

Сервис предназначен для интеграции с существующими информационными системами через программный API. Его результат служит машиночитаемой основой для дальнейшей обработки документов без необходимости вручную перепечатывать их содержимое.

Продукт должен работать с разнородными PDF, в том числе со сканами низкого качества, повернутыми страницами, мелким печатным текстом и сложными таблицами.

## 3. Целевая аудитория

**Непосредственные пользователи продукта** — разработчики и команды интеграции, встраивающие обработку документов в корпоративные и государственные информационные системы.

**Организации, получающие практическую пользу** — государственные учреждения, коммерческие организации и другие участники документооборота, которым необходимо переводить содержимое документов в машиночитаемый вид.

Продукт создается по принципу **API-first**: основной способ использования — программное взаимодействие, включая асинхронную постановку задач и получение результатов обработки.

## 4. Ценность продукта

Сервис призван:

- сокращать трудозатраты на перенос печатного содержимого документов в электронные системы;
- ускорять подготовку документов к дальнейшей автоматизированной обработке;
- создавать машиночитаемую основу для цифровизации бумажных архивов;
- обеспечивать подготовку текста и структуры документов для поиска, анализа и интеллектуальных систем;
- упрощать интеграцию разнородных PDF-документов в существующие процессы организаций.

Сервис решает задачу **структурного извлечения содержимого**. Преобразование результата в учетные записи конкретных систем, например 1С или ERP, выполняется внешними приложениями.

## 5. Область первой версии продукта

### Поддерживаемые возможности

| Область | Описание |
|---|---|
| Входные данные | PDF-документы, включая сканированные, цифровые и смешанные страницы |
| Печатный текст | Извлечение текста с сохранением последовательности чтения |
| Логическая структура | Восстановление заголовков, абзацев и порядка блоков |
| Таблицы | Извлечение содержимого и структуры таблиц, в том числе сложных |
| Многостраничность | Обработка всех страниц документа в исходной последовательности |
| Результат | Структурированный Markdown, пригодный для машинной обработки |
| Интеграция | Программный API и асинхронная обработка задач |
| Автоматизация | Работа без обязательного участия оператора при обработке каждого документа |
| Модели | Заменяемые открытые модели с лицензиями, допускающими коммерческое использование без платы за применение |
| Оценка качества | Воспроизводимое автоматизированное сравнение результатов распознавания и вычислительных затрат |

### За пределами первой версии

- Распознавание рукописного текста.
- Распознавание и интерпретация подписей и печатей.
- Извлечение и интерпретация изображений, графиков и схем.
- Извлечение специализированных реквизитов по бизнес-правилам конкретной организации.
- Автоматическое внесение данных в 1С, ERP и другие внешние системы.
- Реализация собственной системы электронного архива, поиска или анализа документов.
- Обязательный графический интерфейс пользователя.

Наличие на странице неподдерживаемых элементов не препятствует обработке печатного текста и структуры. Такие элементы игнорируются.

## 6. Продуктовые принципы

**Универсальность.** Сервис ориентирован на разные типы документов и не зависит от единого шаблона или отраслевой формы.

**Сохранение смысла и структуры.** Приоритет отдается точности печатного текста, логическому порядку чтения и восстановлению таблиц, а не визуальному воспроизведению страницы.

**Автоматизация.** Обработка документов должна выполняться без обязательного ручного контроля каждого результата.

**Независимость от модели.** Модели распознавания должны быть заменяемыми, чтобы можно было использовать и сравнивать разные реализации.

**Экономическая доступность.** Для распознавания используются открытые модели, допускающие коммерческое использование без лицензионных платежей за их применение.

**Измеримость качества.** Результаты обработки оцениваются воспроизводимыми метриками, а не субъективным впечатлением от сформированного Markdown.

**Интегрируемость.** Сервис предоставляет предсказуемый программный интерфейс для включения в существующие процессы обработки документов.

## 7. Критерии успеха

Успешность продукта определяется следующими характеристиками:

- **Точность текста:** минимизация ошибок распознавания печатных символов и слов.
- **Сохранение структуры:** корректное восстановление заголовков, абзацев, таблиц и порядка чтения.
- **Устойчивость:** работоспособность на разнородных документах, включая некачественные сканы.
- **Производительность:** приемлемые время обработки и потребление вычислительных ресурсов.
- **Надежность:** предсказуемое выполнение задач и корректная обработка ошибок.
- **Воспроизводимость:** возможность объективно сравнивать модели на одинаковом наборе документов и условиях обработки.

Качество распознавания и ресурсная эффективность рассматриваются совместно: продукт должен обеспечивать практически полезный результат без неоправданно высоких затрат на вычисления.
